# 架构师 + 工程师 · 多模型 Agent 编排器

> Kimi K3（架构师：拆解 + 基于证据验收） × DeepSeek V4-Flash（工程师：高频执行）
> 设计蓝本：《深入理解 AI Agent》（李博杰）——管理者模式（10.4.4）+ 提议者-审核者范式（10.4.3.2）
> 配套参考代码：`../ai-agent-book/chapter10/book-translation/`

## 它是什么

一个**成本感知的多模型编排框架**：贵而强的模型只做规划和验收（调用少、上下文长），
便宜而能干的模型承担高频执行（读写文件、跑命令、迭代修复）。
两者**不共享上下文**，只通过结构化"移交包"通信。

```
用户任务
   │
   ▼
架构师 (Kimi K3)  ── 拆解 ──▶ 移交包 {goal, acceptance, facts, refs, budget}
   │                              │
   │                              ▼
   │                     工程师 (V4-Flash) ReAct 循环
   │                     read/write/list/run_command + finish
   │                              │
   │                              ▼
   │                     验证器（真实执行验收命令，产出证据）
   │                              │
   └─── 基于证据验收 ◀──── review {pass / rework + fix_instructions}
        （模型不能批准自己的完成）
```

## 快速开始

```bash
cd architect-engineer
pip install openai pyyaml

# 设置两个 API key（PowerShell）
$env:KIMI_API_KEY="sk-..."       # platform.kimi.com
$env:DEEPSEEK_API_KEY="sk-..."   # platform.deepseek.com

# 跑第一个任务
python orchestrator.py "写一个 Python 脚本，读取当前目录所有 .md 文件，统计总行数并输出 report.txt，要求脚本本身能跑通"
```

每次运行生成 `runs/<时间戳>/`：
- `cost.jsonl` —— 每次模型调用的 token 与费用（缓存命中分开计价）
- `handoffs/` —— 完整的移交包与验收记录（可追溯、可审计）
- `workspace/` —— 工程师的产出文件
- `report.json` —— 最终报告

## 设计决策与书中依据（简历叙事素材）

| 决策 | 依据 |
|---|---|
| 最强模型给规划者而非执行者 | Plan-and-Act 实证：弱规划者是系统最大瓶颈（10.4.4） |
| 双模型不共享上下文，只传移交包 | 10.4 不共享上下文 + K3 官方约束（不可接续异源历史） |
| 移交包三要素：任务+验收 / 事实+约束 / 文件引用 | 10.4.5 MetaGPT 移交包模式 |
| "完成"由验证器证据判定，不由模型宣布 | 10.4.3.1 Loop 工程：模型可以提出完成，不能批准完成 |
| 审核者必须读独立证据（执行结果），不是"再看一遍" | 10.2 新信息判据：无新信息的协作无效甚至有害 |
| 状态栏（轮数/计数/预算）纯代码维护注入 | 2.6 上下文蒸馏：LLM 批量统计自己的历史反而出错 |
| 命令黑名单 + 路径越界拒绝 + 预算上限 | 1.2.2 约束：故障安全默认值 |
| 连续失败升级人工 | 1.2.6.2 人工干预触发条件 |
| 模型名/端点/价格全部在 config.yaml | 1.2.4 模型迭代极快，配置化才能活过模型换代 |
