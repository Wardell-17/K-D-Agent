# 任务描述模板（交给 orchestrator.py 前自查）

## 公式

**做什么**（动作 + 输入在哪）+ **做成什么样**（输出文件 + 格式要求）+ **怎么算完成**（验收命令）

## 模板

```
读取 {输入目录/文件}，{要执行的动作}，输出 {文件名}，
要求：{格式/字段/数量等硬性要求}。
验收：!{一条能真实运行、成功返回0的 python 检查命令}
背景约束：{执行者必须知道的领域规则、术语、禁忌}
```

## 好例子 ✅

```
读取 input/ 下所有 .txt 文献摘要，按研究主题分类，输出 summary.xlsx，
每行含：文件名 | 主题分类 | 核心结论(≤50字) | 关键数据。
验收：!python -c "import openpyxl; ws=openpyxl.load_workbook('summary.xlsx').active; assert ws.max_row>=10; print('OK')"
背景约束：分类只允许用 事故成因/道路设计/行为干预/政策法规 四类；
所有结论必须来自原文，禁止推测。
```

## 坏例子 ❌

```
"帮我整理一下这些文献"        ← 没有输出定义，没有验收标准，系统只能瞎猜
"把文件处理好，注意质量"      ← "质量"无法被验证器检查
```

## 自查清单（运行前过一遍）

- [ ] 输入文件放在项目目录下（如 input/），任务里写明了路径
- [ ] 输出是具体文件名 + 具体格式（xlsx/csv/md/json）
- [ ] 验收命令是 Windows 能跑的（python -c 最稳），我自己先手动试过一次
- [ ] 禁止事项写清楚了（你的"宁缺毋滥"原则：不允许编造来源）
- [ ] 长任务拆得动吗？超过 10 篇文献/多个步骤的，先跟我（Kimi Work）讨论再跑
