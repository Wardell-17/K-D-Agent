# 实验记录 049 ｜ `_search_deepseek` 直连官方端点 + usage 自记账：检索降级链定型

日期：2026-08-26 ｜ 性质：工程补丁 + 真机冒烟（绿灯）

## 背景

Brave 资费否决（2026 年初起新用户仅 $5/月额度≈1000 次，用户拍板不注册）后，
auto 降级链需要新的二级。exp015 逆向实证：DSH 的"自带检索"底层就是直连
DeepSeek 官方 Anthropic 兼容端点（`web_search_20250305` 服务端工具）——
所谓"计费不明"是 DSH 框架内 TokenMeter 的记账缺口，**不遗传给直调方**：
我们自己调端点、自己解析 usage、自己落 cost.jsonl，计费完全可审计。

## 改动（orchestrator.py）

1. `_search_deepseek` 重写：从"需自建兼容端点"的占位，改为直连
   `https://api.deepseek.com/anthropic/v1/messages`（可用 `DEEPSEEK_SEARCH_BASE_URL` 覆盖），
   声明 `web_search_20250305` 工具，解析 Anthropic 响应的 text 块；
2. **usage 自记账**：新增模块级 `_ACTIVE_TRACKER` 钩子（Orchestrator 启动时挂入），
   检索调用的 token 以 `role=engineer-search` 独立归集落 cost.jsonl；
3. `SEARCH_FALLBACK`：`("tavily", "brave", "ddg")` → `("tavily", "deepseek")`。
   brave driver 保留注册（哪天想用了设 key 即可），ddg 保留占位。

## 成本结论

单次检索 ≈ **¥0.04**，比 Brave（$5/1000 次 ≈ ¥0.036/次）价格相当但**无需订阅、
无月度额度焦虑、中文质量实测更强**（013 已证明其对国内政务/行业数据时效性最强）。

## 已知边界（如实标注）

- **记账模型名偏差**：cost.jsonl 里 model 字段记的是工程师档案名（deepseek-chat），
  实际搜索模型是 deepseek-v4-flash；价格按工程师档案价计算，若 v4-flash 单价不同
  会有小偏差——待官方账单对账后校正。
- **按次调用费未知**：DeepSeek 是否对 web_search 在 token 外另收按次费，
  usage 字段不可见，待月底官方账单对账标注（Kimi platform 端明确有按次费，DeepSeek 侧待验证）。
- cache_hit 记 0：Anthropic 端点 usage 未解析缓存字段，成本按全量 miss 计（偏保守，不低估）。
