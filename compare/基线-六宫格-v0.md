**规划溢价 ≈ ¥0.5~0.8/单**——系统自行侦察与探索的 token 消耗。
结论口径：对"用户只给一句话"的真实场景该溢价成立（替代人工设计）；
对批量同构任务，人工拟一次卡反复用更省。
046 归因细化：自主成本大头在 SQLite 迁移**执行层**（13 文件改写），
人工卡只能省规划税、省不了执行税——溢价幅度与任务"侦察/执行"占比正相关。

## 三、L 档研判（轮次范围是否调整）

结论：**轮次纪律不动（25-30 档），L 档按子类分价**。依据：

1. 预算是天花板不是目标：L 桶命中率 86% 但返工才是成本放大器
   （超预算 13 单全部伴随返工/重型卡盒）；
2. 反证：036（75 轮）¥1.51 > 038（85 轮）¥1.14——成本与轮次总额无关；
3. L-04 的 ¥4.06 来自 14 万字符深读 + 2000 样本差分的 token 吞吐，非轮次；
4. 子类价差显著：L-code（038/039/043）¥1.14~3.14 vs L-read（040-042）¥1.78~4.06，
   混算均值（¥1.107）对两类都会误报——**对外报价必须分子类**；
   code 类内部另需区分增量开发（¥1.1~1.3）与存量迁移（¥3+，043 实证）；
