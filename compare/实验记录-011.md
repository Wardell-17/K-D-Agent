# 实验记录 011 —— 审批门（--plan-only）：人在环路的规划确认

- 日期：2026-08-17
- 实验人：Wardell（提案）+ Kimi（实现）
- 关联：README 第 8 节"审核者本身会错"；008（卡盒模式）

## 背景（用户提案）

宏观项目需求往往包含甲方具体要点，直接一句话丢给系统有两个风险：表述不清、
架构师理解与预期有偏差。提案：架构师先拆卡 → **人审卡确认** → 再放行执行。
价值：纠偏成本最低的时点是执行之前——卡片阶段改几个字零成本，执行后返工烧 token。

## 实现

新增 `--plan-only` 模式：架构师拆卡落盘后即退出（只花 1 次规划调用的钱），
终端打印卡片目录与放行命令；人审阅/直接修改 .md 卡片后，用 `--cards <目录>` 放行。
改动约 20 行，复用 `--cards` 零重复逻辑。

## 验证

任务：collect.py 收集 .py 模块名 + readme_gen.py 生成 README_MINI.md（t2 依赖 t1）。

| 步骤 | 结果 |
|---|---|
| `--plan-only` 拆卡后停止，不执行 | ✅ 仅 1 次架构师调用，无工程师调用 |
| 卡片正确（含依赖标注 t2→t1） | ✅ |
| 审卡后 `--cards` 放行，两卡串行（依赖）全 done | ✅ 产物 modules.txt / README_MINI.md 正确 |

### 成本账本（两步合计）

| 环节 | 调用 | 成本 |
|---|---|---|
| 拆卡（plan-only，K3 ×1） | 1 | ≈ ¥0.008 |
| 放行执行（K3 验收 ×2 + DeepSeek ×12） | 14 | ¥0.0488 |
| **合计** | | **≈ ¥0.057** |

## 结论

审批门成立且便宜：一次规划调用（不到 1 分钱）换"执行前的纠偏机会"。
推荐工作流定型：**需求模糊/涉甲方要点 → `--plan-only` 审卡 → 放行；需求清晰 → 直接跑。**
此模式同时产出"需求校准"的副产物——审卡过程本身就是人确认"Kimi 理解的 == 我想要的"。

## 复现方式

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File D:\agent-project\compare\run-mvp-plan.ps1   # 拆卡
powershell -NoProfile -ExecutionPolicy Bypass -File D:\agent-project\compare\run-mvp-release.ps1 -TasksDir '<卡片目录>'  # 放行
```
