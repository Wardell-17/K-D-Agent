## 本单逮到的缺陷：模型输出截断 → 工具参数 JSON 残串崩溃

跑批中途工程师一条消息的 tool arguments 被 max_tokens 截断，
orchestrator 解析时 `json.decoder.JSONDecodeError: Unterminated string` 直接崩溃。

修复（orchestrator.py，注释标"实验 042 防御"）：解析失败时 try/except 兜底，
回灌一条"参数被截断，请拆小写入重试"的 tool 消息让工程师自愈，而不是整单炸掉。
`--resume` 续跑后 5/5 全绿。语法已验证。

## 抽查插曲（诚实记录）：一次虚惊与一条观察项

独立复验时我用大写头名抽查 4 条（`If-None-Match` 等），全部返回 `proceed`，
疑似"前提头被无视"大雷。读源码后发现：cond_eval.py 的接口契约明确声明
"Request header fields keyed by **lowercase** field name"——归一化责任在调用方。
用全小写头名重跑：**304 / 412 / 412 / proceed，全部正确**，虚惊一场。

观察项（不算验收失败）：HTTP 规范要求头字段大小写不敏感，本实现把归一化
放在调用方契约而非 evaluate() 内部。对库使用者是隐性踩坑点，
若做 v2 应在入口处统一 `k.lower()`。
