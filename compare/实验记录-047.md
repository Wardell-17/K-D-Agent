# 实验记录 047 ｜ Brave Search driver 入链：检索降级的第二额度池

日期：2026-08-26 ｜ 性质：工程补丁（检索层可插拔 driver 的首次扩容）

## 背景

Tavily 免费档 1000 次/月，额度耗尽后 auto 链只剩 ddg——而 014 已实测
DDG/Bing 免费 HTML 抓取在当前网络环境全灭（反爬 202/机器人填充页），
降级等于没降级。需要第二个**独立免费额度池**。

## 改动（orchestrator.py）

1. `_http_json` 增加可选 `headers` 参数（Brave 需要 `X-Subscription-Token` 鉴权头，
   既有调用签名不变）；
2. 新增 `_search_brave`：Brave Web Search API（免费档 2000 次/月），
   `BRAVE_API_KEY` 环境变量驱动；无 key / 429 / 无结果一律返回 None 让位降级链；
3. `SEARCH_FALLBACK` 从 `(tavily, ddg)` 改为 `(tavily, brave, ddg)`；
   `search_backend` 卡级路由可选值同步加 brave。

## 冒烟验证（无 key 条件）

- `SEARCH_DRIVERS['brave']` 无 key 时优雅返回 None（不炸链）✓
- 未知后端报错文案含 brave ✓；语法检查通过 ✓
- **真 key 联通性待用户注册后补测**（Brave Search API 免费档需 brave.com 注册）

## 分层降级策略（本次定型）

```
一级：Tavily（1000 次/月，账本内）
二级：Brave（2000 次/月，独立池，账本内）
三级：总控/架构师检索前移（K3 联网取证 → 写进卡片事实；端点可行性待冒烟）
末级：诚实失败（标注未核实，绝不静默降级到垃圾信源）
```

原则：降级的每一级都必须"证据可入账本"——出账本的降级既丢质量又丢审计（013 教训）。
