## 勘误（当日自查发现，2026-08-25 补记）

**上述 ¥0.7087 不是干净数据。** 事后追查发现：当天因 0 字节日志误判"后台没起来"，
实际先后有 **3 个编排器进程对同一盒卡并发执行**（runs/111011、111204 均独立跑完全程，
111051 半途被杀），加上最终 resume 的 105950，同一任务被执行了近 4 遍：

| run | 结局 | 成本 |
|---|---|---|
| 111011 | 全程跑完，4/4 pass | ¥1.4403 |
| 111051 | 被杀 | ¥0.1214 |
| 111204 | 全程跑完，4/4 pass | ¥1.1949 |
| 105950（resume） | 全程跑完，4/4 pass | ¥0.7087 |
| **合计燃烧** | | **¥3.4653** |

两个修正结论：
1. **成本账从未丢失**——cost.jsonl 本来就是逐条落盘，账目只是散进了孤儿 run 目录
   （`--cards` 每次都新开时间戳目录）。真正的问题是并发与目录碎片化，不是缓冲。
2. **105950 的 ¥0.7087 偏低失真**：resume 跑批时工作现场已有前序并发进程的产物，
   工程师捡了现成。治理有效性的结论依然成立，但依据应改为——四套同样的卡在
   三个独立进程中**全部 4/4 通过**（治理前一盒卡 3/4 升级），验收命令落地性经受了
   重复执行检验；干净的单跑成本数字需另跑一单补测。

## 治理动作（由本次事故直接产出）

1. **run 锁**：同一 run 目录同时只允许一个编排器进程（锁文件记 PID，进程死亡自动失效）；
2. **`--cards` 复用目录**：卡盒是某 run 的 tasks/ 时复用该 run 目录，不再新开孤儿目录；
3. **行缓冲**：stdout/stderr 改 line_buffering——被杀也留现场，0 字节日志不再误导监控；
4. 监控纪律（人机共用）：判断进程死活看 events.jsonl/cost.jsonl，不看 stdout 日志体积。


## 结论

- 036 治理有效：**"验收命令必须落地"这一条纪律，直接把自主拟卡模式从不可用拉回可用**——
  同一盒治理后卡片在三个独立进程中全部 4/4 通过（见勘误），验收命令经受了重复执行检验。
- 规划质量是最大成本杠杆的论断（036）获得第二次证实。
- 流程资产确认：`plan-only → 人工审卡 → --cards 放行` 是重型任务的标准姿势，
  本次人工审卡仅改路径一处即放行，审卡成本约 1 分钟。
- 已知残留：后台 nohup 跑批在本沙盒会被静默杀掉，
  重型跑批应以前台分段 + `--resume` 执行（与 kd_dispatch 失效同源）。
- 干净的"治理后单跑成本"待补测一单（勘误第 2 条）。
