# 实验记录 003：迁移主机后 Web 版 403 排查（`transport failure for /api/settings.describe`）

日期：2026-08-17 ｜ 背景：项目从笔记本发布到 GitHub，主机 clone 后启动 `run-dsh-web.ps1`，Web UI 设置页持续报 `transport failure for /api/settings.describe: HTTP 403`，会话功能看似正常但设置/模型页不可用。

## 症状

- 首页正常打开，普通 API 正常
- `settings.describe` / `host.describe` / `agentPreset.list` 等接口持续 **403 Forbidden**
- 同一套代码在笔记本上完全正常 →  initially 怀疑迁移漏文件或 key 问题（均被排除）

## 排查路径（假设→验证→排除，全程 curl 实测）

| # | 假设 | 验证手段 | 结果 |
|---|---|---|---|
| 1 | 配置文件在迁移中缺失/被 gitignore | 检查 `dsh-home/profiles/web/cordis.patch.yml`、`settings.yaml` | 排除——均为干净默认态 |
| 2 | Harness 信任栅栏拦非 loopback 访问 | curl 伪造 `Host: 192.168.x.x:3080` | 复现 403；但用户浏览器 Remote Address 显示 `127.0.0.1:3080` 直连，排除 |
| 3 | 系统代理（Clash 7890）劫持 localhost 流量 | 查注册表代理设置 + 经代理重放请求 | 代理确实开着，但 DevTools 显示请求直连 3080，排除 |
| 4 | 浏览器请求与 curl 的请求头差异 | DevTools → Copy as cURL，原样重放 | **命中** |

## 根因

浏览器发出的请求里 `Origin: http://127.0.0.1` —— **端口号被剥掉了**（正常应为 `http://127.0.0.1:3080`）。

Harness 的浏览器信任栅栏（防 DNS rebinding）会比对 Origin 与 Host：Origin 缺 `:3080` → 与 Host `127.0.0.1:3080` 不匹配 → 判定跨站 → 对特权方法集（`settings.*`、`credentials.*`、`agentPreset.*`、`host.listDirectory`、`llm.discoverModels` 等十几个）返回 403。**特权方法即使配了 `DSH_TRUSTED_HOSTS` 也只认 loopback，这是设计如此，不是 bug。**

对照实验：

```
Origin: http://127.0.0.1        → 403 forbidden（完美复现）
Origin: http://127.0.0.1:3080   → 200，返回 {"cwd":"E:\DSH\K-D-Agent","provider":"kimi-code","model":"k3"}
```

剥离端口号的元凶是浏览器侧（Edge 扩展的去广告/隐私规则或 Edge 严格跟踪防护/增强安全性），**InPrivate 窗口（默认禁用扩展）访问即恢复正常**。

## 修复

1. 日常使用：InPrivate 窗口，或找出并停用剥离 Origin 的扩展（逐个禁用二分）
2. 顺带加固：所有启动脚本钉死 dsh 版本 `$DSH_VERSION = '0.1.0-rc.6'`（升级流程见 README 6.1 节）——排查中发现 `npx -y` 不锁版本，而 rc.5→rc.6 之间栅栏行为已变过一次，官方 Discussion #764 也有 rc.5 上 `127.0.0.1` 被拦而 `localhost` 正常的案例

## 经验沉淀（排查同类问题的顺序）

1. 先分清"服务端拦的"还是"路上被改了"：curl 直连能过 → 服务端无辜，去查浏览器/代理
2. DevTools 三板斧：Remote Address（是否直连）→ Copy as cURL（拿到真实请求）→ 原样重放 + 逐头二分
3. Harness 403 特征码：首页能开 + 特权 API 403 = 信任栅栏；整条 API 都 403 = 先看 Host 是否 loopback
4. 迁移类故障先验"两端环境差"（浏览器/扩展/代理/版本），再验"代码差"
