# 实验记录撰写流程（本项目标准）

本项目的铁律：**结论必须带证据，证据必须可复现**（宁缺毋滥）。写实验记录不是写作文，是把一次运行的"账本"固定下来。

## 步骤

1. **定编号**：列出 `compare/` 目录下已有的 `实验记录-*.md`，取最大编号 +1（如已有 001~003，新记录为 004）。

2. **取账本**（如果是 Harness 运行）：运行项目根目录下的官方账本脚本（**必须用绝对路径，不假设当前工作目录**）：
   ```
   python D:\agent-project\compare\analyze_session.py
   ```
   不传参数时自动分析最近一次运行（主会话+子代理）。把输出的模型、LLM 调用数、token 明细、估算成本、耗时原样放进记录表格。**不要凭记忆写数字**。如需指定历史会话，传会话目录路径（在 `dsh-home/sessions/<目录名>/<会话id>/` 下）。
   **如果脚本不存在或报错，如实记录"账本工具不可用"并把报错原文贴进记录——不要现场重建一个账本工具，那是另一个任务，不属于本流程。**

3. **取证据**：列出本次运行产生的文件（产物路径、report.json、会话 id），能引用的都给出相对路径。

4. **按模板写记录**（见下方模板），保存为 `D:\agent-project\compare\实验记录-NNN.md`（绝对路径；不要存到任务工作目录里，那些目录可能不入库）。

5. **联动检查**：
   - 若本次实验改变了结论或新增组件 → 提醒更新 `README.md` 对应章节
   - 若踩了新坑 → 必须写进"踩坑清单"（这是简历素材，一条都别丢）
   - 若判据有变化 → 提醒更新 `决策框架.md`
   - 完成后提醒用户提交 git（"离开前 push，开工前 pull"）

## 写作纪律

- 数字必须来自账本或实际文件，禁止估算冒充实测；订阅端点的成本标注"（订阅估算值）"
- 失败也要记：失败实验的价值不低于成功（参见实验记录 002/003）
- 单样本结论必须标注"样本量=1，待累积"
- 对比实验（两条路线/两种模式同任务对照）用双列对照表（参照实验记录 001 的格式），不用角色账本表
- 全程中文，术语可中英混用
